==========================================
前提条件：PC、ソフトウェア、ネットワーク
==========================================

この章では、セットアップを始める前に確認しておくことと、用意しておくものをまとめます。不明な点は、ハッカソン運営の案内を優先してください。

2 台の PC の役割
------------------

.. list-table::
   :header-rows: 1
   :widths: 1 1 3

   * - 役割
     - マシン
     - 主なソフトウェア
   * - シミュレータ
     - Windows PC
     - Unity Editor 2022.3.62f3 または配布ビルド、AGX Dynamics for Unity
   * - ミドルウェア
     - Linux PC
     - Ubuntu 22.04、ROS 2 Humble、colcon（ホストに直接インストール）

シミュレータとミドルウェアは、別々のマシンで動かすのが基本です。接続は Windows 側（クライアント）から Linux 側（サーバー）へ張る 1 本の TCP 接続で、この接続の上を双方向（full-duplex）にデータが流れます。Windows 側に待ち受け用のポートを開ける必要は通常ありませんが、接続の確立後も双方向のパケットと応答が通る必要があります。ファイアウォールや VPN が「Windows から Linux への新しい接続」だけを許可する設定だと、接続後に通信が途切れることがあります。困ったときは :doc:`troubleshooting` のネットワークの項を参照してください。

Windows 側のバージョン
------------------------

リポジトリの設定ファイルで確認できる値は、次のとおりです。

- **Unity**：2022.3.62f3（ ``ProjectSettings/ProjectVersion.txt`` ）。Unity Hub からインストールします。
- **AGXUnity**：5.1.1+6f490ac5、Windows 向け、AGX Dynamics 2.38.0.1（ ``Assets/AGXUnity/package.json`` ）。 ``Assets/AGXUnity`` 以下に同梱されているため、別途ダウンロードする必要はありません。
- **必要な AGX モジュール**：Core、Particles、Granular、Terrain、Tracks（既存の README の記載に基づきます）。モジュール構成、試用期間、再配布の可否はベンダーが決めるため、このマニュアルでは保証しません。
- **ビルド設定**：Standalone 向けのスクリプティングシンボルに ``ROS2`` が定義済みです。ビルドのターゲットは Windows x86_64、スクリプティングバックエンドは Mono です。AGXUnity と同梱パッケージは、勝手に更新したり差し替えたりしないでください。

Linux 側のバージョン
----------------------

- **OS**：Ubuntu 22.04 を使います。
- **ROS 2**：Humble をホストに直接インストールします。
- **開発ツール**：git、colcon、rosdep を使い、 ``$HOME/opera-ws`` にミドルウェアをビルドします。導入手順は :doc:`linux-middleware` を参照してください。
- **Docker での動作テスト**：一連の動きを手軽に試したい場合は :doc:`sample-run` を参照してください。Docker、rocker、任意の NVIDIA Container Toolkit は、この方法を選ぶ場合だけ必要です。

ネットワーク要件
------------------

- Windows PC と Linux PC が、同じ LAN（または相互に通信できるネットワーク）にあること。
- Linux 側で TCP の **10000** 番ポートを待ち受けできること。 ``ros_tcp_endpoint`` の launch ファイルは、 ``ROS_IP=0.0.0.0`` と ``ROS_TCP_PORT=10000`` を設定します。 ``0.0.0.0`` は待ち受けアドレスであり、Windows 側に入力する接続先 IP アドレスではないので注意してください。
- 通信は、Windows 側から張る 1 本の TCP 接続の上を双方向に流れます。Windows 側に受信用のポートを開ける必要は通常ありませんが、双方向のパケットと応答が通る必要があります。Linux 側の受信許可と Windows 側の送信許可の両方が有効になっていることを確認してください。
- Linux 側に複数の NIC がある場合、Windows に入力する接続先 IP アドレスは、 **Windows と同じ LAN につながっている側の IPv4 アドレス** にします。 ``127.0.0.1`` 、 ``docker0`` などのブリッジ、VPN 側のアドレスが正しいとは限りません。

運営に確認しておくこと
------------------------

セットアップの前に、ハッカソン運営から次の情報を受け取っているかを確認してください。配布方法や有無は、イベントごとに異なります。

- ソースリポジトリ（このリポジトリ）へのアクセス方法
- ビルド済みプレイヤー（バイナリ）を配布するかどうかと、入手方法
- AGX Dynamics のライセンスの手配方法（自分で評価版を申請するのか、運営経由なのか）
- サンプルミドルウェアの入手方法と使用するブランチ（ :doc:`linux-middleware` にクローンとビルドの手順があります）
- 会場ネットワークの IP アドレスの割り当て方法（固定 IP か、DHCP か）。Windows 側の接続先 IP アドレスは、この Linux 側の IP アドレスになります。
